# Demo-capture sandbox

## Why this directory exists

A typical Linux desktop session runs on Wayland, and a Wayland compositor does
not expose the desktop to X11 clients. `ffmpeg -f x11grab` against such a
session captures a near-black frame rather than the screen, and there is no
X11 input automation to drive the editor with. Recording VS Code therefore
needs a virtual X display, and that is what this container provides.

## What it produces

[`images/demo.gif`](../images/demo.gif) — the animation at the top of the
extension's README and of the Marketplace listing. It is generated by the
scripts here, not assembled by hand, so it can be regenerated when the editor
experience changes.

It is build tooling, not extension runtime: `docker/**` is excluded from the
packaged `.vsix`.

## Prerequisites

- Docker.
- Local checkouts of `zenzic` (the engine) and this repository, mounted
  read-only. The engine is installed editable from the mount; nothing in the
  container writes back to it.
- A provenance verifier script, mounted at
  `/home/demo/verify_local_provenance.py`. It proves the recording captured
  the local checkouts rather than the published release, and `record-demo.sh`
  refuses to record without it. Maintainer-supplied; point
  `PROVENANCE_SCRIPT` elsewhere to override the path.

## Build

```bash
docker build -t zenzic-demo:rec docker/
```

## Regenerate the demo GIF

One command spans record → encode → seed palette → verify:

```bash
mkdir -p .demo-out && chmod 777 .demo-out
docker run --rm \
  -e SCREEN_GEOMETRY=1600x924x24 \
  -e DEVICE_SCALE_FACTOR=2 \
  -e CAPTURE_HEIGHT=900 \
  -v /path/to/zenzic:/mnt/zenzic-core:ro \
  -v "$PWD":/mnt/zenzic-vscode:ro \
  -v /path/to/verify_local_provenance.py:/home/demo/verify_local_provenance.py:ro \
  -v "$PWD/docker/record-demo.sh":/home/demo/rec.sh:ro \
  -v "$PWD/.demo-out":/out \
  zenzic-demo:rec bash /home/demo/rec.sh

cp .demo-out/demo.gif images/demo.gif
```

Expect five to ten minutes. The run prints each stage; it ends with
`PASS: proportion and colour fidelity both verified` and the accepted file's
SHA-256.

That SHA-256 differs on every run and is not a reproducibility check: this is a
capture of a live editor, so diagnostic timing and cursor-blink phase vary
between takes. What is reproducible, and what the gate enforces, is the set of
measured properties — 800×450, 12 fps, ~14.9 s, glyph x-height 8-9px, and both
meaning-carrying colours present exactly. Two consecutive runs differed by 2.9%
in bytes and by one pixel in one colour count. On any failed check it writes no GIF at all — `demo.mp4` is kept so
the encoding half can be re-run on its own:

```bash
docker run --rm \
  -v "$PWD":/mnt/zenzic-vscode:ro -v "$PWD/.demo-out":/out \
  --entrypoint bash zenzic-demo:rec /mnt/zenzic-vscode/docker/encode-demo.sh
```

`scripts/verify_demo_gif.py <gif>` runs the same checks against any GIF, and
`--self-test` exercises the instrument without one.

## The other scripts here

| Script | What it does |
| :--- | :--- |
| `record-demo.sh` | The take. Ends by calling `encode-demo.sh`. |
| `encode-demo.sh` | MP4 → GIF, then the gate. Writes nothing if it fails. |
| `capture-squiggle.sh` | Environment proof: provenance, activation, one frame. |
| `record-precommit-demo.sh` | The pre-commit refusal clip, for the core README. |
| `record-lab-demo.sh` | `zenzic lab z201`, for the security examples page. |
| `render-compare.sh` | Captures one frame at a given geometry and zoom level. |

The last two build on [`Dockerfile.recorder`](./Dockerfile.recorder) (393 MB), not on the editor image
(1.74 GB): a terminal recording needs a pty, a Python and a renderer, and no
editor.

```bash
docker build -f docker/Dockerfile.recorder -t zenzic-recorder:1 .
docker run --rm \
  -v /path/to/zenzic:/work/zenzic:ro \
  -v "$PWD/.demo-out":/out \
  -v "$PWD/docker/record-lab-demo.sh":/home/demo/rec.sh:ro \
  --entrypoint bash zenzic-recorder:1 /home/demo/rec.sh
```

## Failure modes that are not self-evident

- **`SCREEN_GEOMETRY` must be passed.** The entrypoint defaults to
  `1280x800x24`, which at `DEVICE_SCALE_FACTOR=2` halves the logical viewport
  and doubles the size of every glyph in the output.
- **`CAPTURE_HEIGHT` must leave 22 device pixels** below it for the window
  manager's own toolbar, or the toolbar is in frame. The screen must be at
  least `CAPTURE_HEIGHT + 22` tall.
- **`x11grab` fails outright** if the requested geometry exceeds the display,
  and every later measurement then reads an empty value rather than erroring.
- **`.demo-out` must be world-writable**: the container runs as uid 1000 and
  the scripts refuse to start if `/out` is not writable.
- **`xdotool search` exits 0 with empty output** when it finds nothing, so
  waiting on its exit status never terminates. Wait on a window id.
- **The editor image is not derived from `Dockerfile.recorder`** and vice
  versa; building one does not provide the other.

## Where the reasoning lives

This file is how to run it. Why each parameter has the value it has — what was
measured, which alternatives were tried, and the defects that produced the
current checks — is maintained separately by the maintainer and is the
canonical source if the two ever disagree.
